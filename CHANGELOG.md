# Changelog

All notable changes to **Music Manager** are listed here, newest first. Versions before 2.1 Beta 1 were internal builds (the project was called *Garmin Music Manager*); they are summarised at the end.

Music Manager is an independent project, not affiliated with or endorsed by Garmin or Apple.

## 2.5 — build 50 (final release)

First published release since 2.3. It contains everything of the internal 2.4 build (never published, listed below) plus the work done after it: online artwork search through the artist's whole discography, the «songs without cover» filter, fixed arrows in Fix Artwork, the redesigned welcome window, the prompt before duplicating files in «Direct Copy», and the «No Genre» filter fix. Release text: `docs/RELEASE-NOTES-2.5.md`. Not compiled by the assistant: compile and test in Xcode.
- **Legal Notices.** The text now says that network libraries can also be read from the JSON file of MusicManager Server and that podcasts are read from files Apple Podcasts has already downloaded (`Localization.swift`, `about_legal_text`).
- **Acknowledgements.** `docs/RELEASE-NOTES-2.5.md` thanks mcoliver for the idea behind Podcasts (his MIT-licensed script `fixPodcastMetadata`; no code used) and for the CI proposal (issue #2).
- **TESTING.md.** New section «2.5 — what to test» (welcome window, Wi-Fi off, Podcasts, Server, Fix Artwork, filters, Direct Copy, PacePro, Go to, profiles).
- **Version.** `project.yml`: 2.5, build 50 (build 49 was the last internal build).

- **User profiles (experimental).** Settings ▸ Advanced ▸ Tools has a new switch, «User profiles (experimental)», off by default (off = no button and the app behaves as before). - **Fix: the saved compact copy of a remote library was lost every time.** The copy was named after the file's path, and the path of a network volume is not stable: two servers that share a folder with the same name (here both «MacSSD») mount as `/Volumes/MacSSD` or `/Volumes/MacSSD-1` depending on which is mounted first, so the copy looked missing or invalid and the whole file was copied again (Milano over VPN: 30 MB in 25 s, versus 2 s from the copy; the server's files had not changed). The copy is now named after the library's identifier (`RemoteLibraryConfig.id`), with the old path-named copy adopted at the first opening (renamed) and any other old copy deleted when the new one is saved (`ExternalParsed.cacheURL(for:key:)`, `loadCacheFile`, `saveCacheFile`, `removeCache(forXMLPath:key:)`). Not compiled by the assistant. Backups: `MusicLibraryService.swift.prima-chiave-copia`, `AppSettings.swift.prima-chiave-copia`.

Used for user profiles: switch on (first user created), new user (start from current settings or defaults), user switch (from n. A to n. B), delete, switch off, switch refused while an operation is running, and the «device of another user» prompt (at connection and after a user switch) with the answer. No names are written (users are indicated by their order number: the log can be sent as diagnostics). «Log level: detailed/normal» is now written only when the level really changes (every user switch reassigned it and rewrote the line). Backups: `UserProfiles.swift.prima-log-utenti`, `AppViewModel.swift.prima-log-utenti`, `MusicManagerApp.swift.prima-log-utenti`, `AppSettings.swift.prima-log-utenti`, `CHANGELOG.md.prima-log-utenti`. - **Diagnostics: list redraw counters.** With detailed logging, the log now reports once per second how many times the Albums/Artists list evaluated its headers, album headers and track rows (`[prestazioni] Valutazioni nell'ultimo secondo`), to find out why opening a group freezes the list for 0.4–0.8 s on huge libraries. The group header also skips scanning its tracks when nothing is selected. The purchased-tracks badge on Album/Artist headers now uses the cached per-group counts instead of scanning the group's tracks. The log also counts which object (view model, settings, player) triggered a redraw (`origine: …`).
- **Huge libraries: no more list redraw from the network check.** Every network path update re-assigned `networkChecked = true` even when it was already true, and any assignment to a published property redraws the whole Albums/Artists list; with thousands of groups that froze the interface for 0.4–2 s every few seconds while idle. It is now assigned only once. Same for the online/offline flag of the shared-library check (`LibraryReachability.isOnline`).
- **Diagnostics: reachability of shared libraries.** With detailed logging, every change of a shared library's state (reachable / not reachable / mounted, with the probe diagnosis) and every network path update are logged (`Raggiungibilità «name»: …`, `Rete: online/offline`), to investigate a library shown as unavailable at first launch.
- **Huge libraries: Album/Artist headers are redrawn only when they change.** The header of an artist or album is now a separate view that SwiftUI compares by value (`GroupHeaderContent`): when the list is re-evaluated for any reason, the headers whose title, subtitle, selection, cover, device state and text size are unchanged are skipped. With thousands of groups, every list re-evaluation used to rebuild all the headers (up to 2 s of frozen interface). Clicks, double-click playback and the context menu are unchanged. Detailed log: `corpo intestazione` counts the headers actually redrawn.
- **Huge libraries with a device connected: «already on the device» arrows are cached per group.** With a Garmin connected, every redraw of the Albums/Artists list checked every track of every group against the device (1–1.7 s on 55,000 tracks). The result is now kept per group and recalculated only when the files on the device or the library change (`deviceIndexRevision`).
- **Huge libraries: closed groups no longer build their content; clicks no longer redraw twice.** Albums/Artists groups built the content of every group on every list pass (thousands of track scans per click on 3,974 albums), and each click on the list also re-assigned `searchTarget` to the same value, which redrew the whole list a second time (1.65 s freeze with the list scrolled deep). Only open groups now build their rows, and `searchTarget` is assigned only when it changes.

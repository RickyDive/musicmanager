# Changelog

All notable changes to **Music Manager** are listed here, newest first. Versions before 2.1 Beta 1 were internal builds (the project was called *Garmin Music Manager*); they are summarised at the end.

Music Manager is an independent project, not affiliated with or endorsed by Garmin or Apple.

## 2.2 — build 19

First final release of the 2.2 line. It brings together everything from Beta 1 (build 17) and from the Beta 1 GH1 test build (build 18), plus the final checks: the quick test on macOS 27.2 (Release Candidate) with the Garmin, USB and remote libraries, AirPlay (HomePod and Apple TV), saving to Music and the unmount at quit. New app icon. See `docs/RELEASE-NOTES-2.2.md` for the text of the release.

- Network libraries, first read of the XML: the file is now copied to a temporary local file in blocks, with live progress («Copying the XML: 12.4 of 49.7 MB (210 KB/s)») in the title-bar capsule, whose ring is GREEN (the library-availability colour); then it is parsed locally and the compact cache is saved as before (later opens stay instant). If no data arrives for 90 s the read stops with a clear message («XML transfer stopped… check VPN/network») shown as an error in the capsule/bell. In Settings the same text appears on the progress line. If the cache is still valid for the XML (same size and date) nothing is copied.
- XML copy progress now counts in decimal MB (1 MB = 1,000,000 bytes), the same figure Finder shows; a stalled transfer is reported as an error (red), not a warning.
- Playback from a network library: while the track loads, the capsule shows a green spinner and «Loading from the remote server… «title»». If it has not started within 20 s the app shows a red error in the capsule and counts a failure (a track that starts resets the count); after 3 failures in a row the app says it is a network-speed issue (not an app error) and offers to turn off playback from remote libraries until the app is closed («Turn off playback» / «Keep on»); when off, double-clicking a remote track asks whether to turn it back on and retry. Browsing, sending to the device and everything else are unaffected.
- Turning playback off applies to remote libraries only (local playback is never affected) and is lifted automatically when another library is opened.
- When playback from remote libraries is turned back on (retry dialog, or opening another library) the notice now says «Playback restored on remote libraries.», replacing the old «turned off» message.
- Quit: network volumes that the app itself mounted during the session (remote libraries) are unmounted when the app closes, so nothing stays connected to the other site. Volumes that were already mounted before (by the user or the system) are left alone; a busy or unresponsive volume is not forced (wait of at most 5 s).
- Playback from a network library: after failed attempts, when a track finally starts the red error is replaced by «Playing from the remote library: …».
- Glass panels: the top panels were measured 2 levels lighter than the bottom ones (253 vs 251 on a screenshot) with the same fill and glass; the top panel now uses the same `GlassEffectContainer` structure as the bottom one. To be checked visually.
- Glass panels (test): the top panel is now drawn with the `.clear` glass variant (more transparent) plus a light blurred veil (`glassTopVeil` = 0.5, adjustable in GlassBars.swift) so that with «Window opacity» at minimum it is clearly see-through like the bottom bar without the text underneath overlapping the panel's own text; the bottom keeps `.regular`.
- Fix (possible cause of the slowdown after going from a network library back to the local one): when the library changes, the album-artwork searches still running (possibly reading slow network files) were only forgotten, not stopped; now they are cancelled. Diagnostics: the log now records, on returning to the local library, how long it took, how many searches were cancelled and the app's memory before/after (to find the real cause if the slowdown persists).
- Speed with big libraries (55,000 tracks): sorted songs, albums and artists were recalculated at EVERY refresh of the browser (tab change, selecting a track, searching) for all the tabs already opened, which caused ~2 s with a spinner when switching tab on a network library. They are now kept in memory and recalculated only when the tracks, the genre filter or the search text change.
- Quit: if a network library was actually used in the session (opened or played), a message without buttons «Disconnecting from network resources…» appears while the volumes are unmounted and closes by itself, so the 2–3 s wait does not look like a freeze; if the volumes were only mounted, the unmount is silent. The unmount no longer blocks the interface.
- Wait-only panel («Disconnecting from network resources…»): no empty space where the buttons would be, a small spinner instead, height fitted to the text.
- Fix: the saved network address (smb://…) of a remote library could be erased, leaving only «/Volumes/MacSSD…» in Settings and red dots after a restart. Cause: two shares with the same name («MacSSD» on Milano and on Mare) get different mount points on each mount (/Volumes/MacSSD, /Volumes/MacSSD-1); the saved path then pointed at a wrong or missing file, address resolution returned nothing and that «nothing» overwrote the known address. Now the address is never erased by a failed resolution, it is not cleared when the path changes, and it is resolved from the library bookmark (current mount point).
- Quit unmount made reliable: the volume of «Mare» stayed mounted because the app only unmounted volumes it had recorded itself mounting (a volume re-mounted by the system when opening a library bookmark was not recorded). Now, at quit, the app unmounts the volumes of the configured remote libraries (XML file and music folder, found through their bookmarks) that were not already mounted when the app started; the player is stopped first to release open files; the detailed log records the result of each unmount («smontato» / «non smontato (reason)»).\n- Quit unmount, busy volume: the second test returned OSStatus -47 (volume busy) for «Mare» right after playing tracks from it, because the player releases remote files asynchronously. Now each volume is unmounted with up to 4 attempts 0.6 s apart (nothing is forced: a volume still in use, e.g. open in Finder, stays mounted and the log says so); the log names the server address of each mount point and the attempt that succeeded; overall cap raised from 5 to 9 s.
- Spinners tied to what the app is doing: operations are now tagged «library» (reading libraries, remote XML copy, saving to Apple Music) or «device» (connect, transfer, delete, device refresh). The spinner in the device panel title row appears only for device operations; the Refresh button spins during library operations and during the whole «Refresh» action it started, not during a transfer or deletion on the device. The title-bar capsule is unchanged.
- Row selection drawn twice (reported on a family Mac): the native table highlight (rounded) could remain visible under the coloured row background when the AppKit table did not exist yet at first layout; `HideNativeSelection` now retries (0, 0.25, 0.8, 2 s) until the table is found.
- Selected rows now use a single rounded-corner highlight in the colour chosen in Settings (`rowHighlight`, corner radius 8, 4 pt side inset) instead of a full-width rectangle; the native highlight stays hidden.
- Software update check, diagnostics: the detailed log now lists the simple fields of each element returned by the Garmin server (no release notes, no URLs), to find which field holds the version shown by Garmin Express (6.73 «System Software Bundle» for the fēnix 9 Pro vs 2.31 «Firmware» reported by the server). No behaviour change.
- Software update check: from the diagnostic log, the Garmin server answers the automatic request with only «Map Region Grouping file» 2.31 (`isPrimaryFirmware=0`, partNumber 006-D9267-00) and its metadata, not the system software 6.73 shown by Garmin Express. New hidden test switch `defaults write com.crdev.MusicManager debugUpdateInteractive -bool YES` sends `IsUserInteractive: true` (as a manual «check for updates»). No change by default.
- Remote library opened from the saved copy: the app now notices when the XML on the server has changed since the copy was saved (size or date differ; only the file attributes are read, no copy) and posts a ⚠️ message «Library “…” has changed on the server: press Refresh to read it again.» in the title bar / notifications. It never re-reads by itself (a slow link could take minutes). Found when a new album added to the library was not shown until a manual Refresh.
- Type-ahead in lists (reported in Artists: typing «Princ» jumped to P and then to C): with a large list the main thread is busy scrolling, so key presses were processed late and the one-second pause was measured at processing time, wiping the typed text. The typed text is now composed in `TypeAheadMonitor` at key time using the keyboard event timestamp, and the view always receives the complete text, so no letter is lost or reset by UI lag.
- Type-ahead feedback (from the user's video and request): the typed text («prince») was drawn at the bottom of the list, under the glass panel, and was barely readable. It now appears in the large letter indicator next to the scroll knob (the one that shows the initial while scrolling): while typing, the indicator shows the typed text on a thicker material, stays visible until the typing pauses, and widens for longer text; the separate centre bubble was removed. The capsule has its natural size (`fixedSize`, at most the last 24 characters) and stays aligned to the right of the scroll bar, growing to the left.
- Type-ahead on remote libraries and external drives: positioning from the keyboard uses only the first typed letter (further letters within the second are ignored), because each scroll is slow on large remote lists. The local library keeps the multi-letter positioning.
- External drive library, diagnostics: when «+» finds no usable registered device (alert «No registered device»), the detailed log now says why for each registered device (copy of GarminDevice.xml missing, no media information, does not accept music, no sendable format). No behaviour change.
- External drive library without a registered Garmin: adding a folder no longer requires a Garmin connected at least once. With no usable registered device the catalog is built with the «Generic Garmin» profile (formats the app can prepare: AAC, M4A, MP3); when a Garmin with different formats is later connected, the existing proposal to rebuild the catalog for it appears. New key `drive_generic_device`; hint text updated.
- App icon: new `AppIcon.icon` (SVG layers without the transparent bounding rectangle, so the colours fill only the glyphs; `icon.json` without the `color-space-for-untagged-svg-colors` key, which older Icon Composer versions cannot read).
- Mount probe: duplicate host candidates (saved server name equal to the address host) are no longer probed twice, halving the wait when the server is unreachable.
- Remote Libraries: new switch «Mount automatically» (Settings ▸ Advanced, next to the «max 3» hint), off by default. Off: at launch only a light check runs and the status dot has three states — filled green = mounted, hollow green = server answers but the volume is not mounted, red = not reachable; choosing a reachable-but-unmounted library in the picker asks «You are connecting to a network resource…», then mounts it (progress in the status line) and opens it. On: the volumes are mounted at launch as before, with an explanatory message. The mounted state is now computed off the main thread (the Settings table no longer touches the network volume while drawing).
- Fix (cause of the slow launch mount found in the log): before opening the share, the launch mount resolved the library's saved bookmark, which made the system try to remount it with the old server name («MacMini ServerM2») and wait about a minute, ending with its own error dialog. The bookmark is now resolved without mounting (`FileBookmark.resolve(_, mounting: false)`); the share is opened only with the address that answered the probe.
- Detailed log: the launch mount of network libraries now logs, per attempt, the saved address, the server host, the probe result and its time, the URL opened and how long the system took to answer (for diagnosing slow mounts).
- Fix: network library mount at launch now opens the share with the server name that actually answered the probe (e.g. «MacMini-ServerM2-2.local») instead of the name shown by Finder («MacMini ServerM2»), which the system sometimes could not resolve — that was the cause of the mount that sometimes worked and sometimes ended after 2+ minutes with the system's own «error while connecting to the server» dialog.
- Settings ▸ Advanced: adding a library is now done with «+» only. Remote Libraries: «+» asks for the XML file (the «Choose XML file» button is gone), then the cursor goes to the Nickname and a name is required before the file is read. External Drive Libraries: after choosing the folder (and device) the cursor goes to the Nickname, a name is required before the scan starts. Leaving the field empty keeps the cursor there (a red hint explains); «−» cancels the addition, and an unnamed row is dropped when the section is closed.
